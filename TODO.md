## Известные грабли (для любого "почему-то не работает")

- **VK меняет разметку без предупреждения.** Свежие случаи: `AudioCatalog_SectionAllTracks` исчез (теперь header + `closest('section')`), `repeatState` — `'audio'`, а не `'one'`. Сначала сверять живую разметку через CDP, не чинить по старым селекторам.
- **НЕ все выпадающие меню VK одинаковы.** Пункты `AudioBroadcastsMenu_*` (трансляция) не кликаются вообще ничем. Пункты `AudioActionSheet_Item_*` (меню "..." трека — share/dislike/mix/альбом/плейлисты) кликаются нормально доверенным кликом. Разница не выяснена (возможно, VKUI Popover vs ActionSheet — разные компоненты) — при столкновении с новым меню проверять кликабельность отдельно, не считать все меню одинаково сломанными/рабочими.
- **Закрытие action sheet: только повторным кликом по той же открывающей кнопке** (проверено — честный тоггл, просто нужна пауза ~700мс). НЕ кликать "в случайную точку экрана" для закрытия — у VK элементы (например, логотип в углу) могут перехватить клик и увести на другую страницу (поймано вживую).
- **VK иногда САМ возвращает каталог на вкладку "Главная"** между независимыми действиями пользователя, не только сразу после навигации — не только `ensureBasePage()` должен об этом знать, любой код, работающий с `AudioCatalog_SectionTracks` (специфично для "Моей музыки"), должен сам переселекчивать вкладку "Все" при необходимости (см. `rowHoverPointScript` в mymusic.js).
- **Кнопки на hover (audiorow-actions) монтируются в DOM не мгновенно** — фиксированной паузы 250мс на все случаи недостаточно, нужен poll (см. `rowActionButtonScript`).
- **VK иногда открывает `/audio` как `/audios<id>?section=all`** — уже обрабатывается (`ensureBasePage`/`spaCleanupScript`/`submitQuery`), но помнить при отладке. Также это нормальный (не "сломанный") URL для вкладки "Все" каталога на некоторых аккаунтах — сам по себе не признак проблемы, признак проблемы — отсутствие нужной секции в DOM.

## Как тестировать живьём

1. `(npx electron . --remote-debugging-port=9333 > /tmp/electron.log 2>&1 &)` — фоново; ждать ~15с (webview-гость цепляется к CDP позже страницы).
2. `curl -s http://127.0.0.1:9333/json` — таргеты (`page` = наш renderer, `webview` = гость VK). Id гостя меняется при каждом reload.
3. В `page`-контексте доступно `window.Shared.webview.executeJavaScript(...)` — читать/кликать DOM VK.
4. Кнопки нашего UI: `document.querySelector('.btn-X').click()` в `page`-контексте. Доверенные клики в webview: `window.Shared.sendTrustedClick(x, y)` (часть кнопок VK слушает только их: play/pause, lyrics, share, открытие меню трансляции).
5. Удобный раннер из этой сессии: scratchpad `cdp.js` (`node cdp.js <targetId> --file <expr.js>` — выражение исполняется с awaitPromise).
